# FlashVote

[🇬🇧 English version](README.md)

Платформа опросов в реальном времени: **Создай → Поделись → Проголосуй → смотри результаты вживую.**

Стек: Next.js 16 (App Router, React 19, Server Components), Tailwind CSS v4,
shadcn/ui и Supabase (PostgreSQL + анонимная аутентификация + Realtime).
Графики — Recharts, QR-коды — qrcode.react.

## Возможности

- Создание опроса без регистрации (анонимная сессия выдаётся автоматически)
- От 2 до 10 вариантов ответа, готовые наборы (Да/Нет, Да/Нет/Не знаю, Согласен/Не согласен), опциональный срок действия
- Уникальная ссылка (`/p/<slug>`) и QR-код для каждого опроса
- Один голос на сессию браузера — контроль на уровне базы данных
- Живые результаты с переключением вида графика (столбцы / кольцо) через Supabase Realtime
- Интерфейс на русском и английском с мгновенным переключением; по умолчанию — язык системы
- Светлая / тёмная / системная тема с мгновенным переключателем
- Управление своим опросом: копирование ссылки / QR / отправка по почте, закрытие и переоткрытие, удаление
- Раздел «Мои опросы» для текущей сессии браузера
- Проработанные состояния: загрузка, пустой список, закрыт/истёк, повторный голос, страница не найдена, офлайн/переподключение realtime

## Быстрый старт

```bash
pnpm install
pnpm dev                     # http://localhost:3000
```

### Переменные окружения

| Переменная                          | Назначение                                     |
| ----------------------------------- | ---------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`          | URL проекта Supabase                           |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY`     | Публикуемый ключ — безопасен для браузера      |

**Интеграция Supabase из Vercel Marketplace** выдаёт эти переменные автоматически
(`NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`);
оба варианта имён поддерживаются (см. `lib/supabase/config.ts`). Локально их можно вытащить:

```bash
npx vercel link
npx vercel env pull .env.local
```

Service-role ключ **не используется вовсе**: вся привилегированная работа
выполняется внутри функций БД `SECURITY DEFINER`.

### Настройка Supabase

1. В разделе **Authentication → Providers → Anonymous sign-ins** включите
   анонимные входы (приложение выдаёт анонимную сессию при первом создании
   опроса или голосовании).
2. Примените миграции (`supabase/migrations`) командой `supabase db push`,
   через CLI или SQL-редактор. Миграции создают таблицы, RLS-политики, RPC
   и добавляют `polls` / `poll_results` в публикацию `supabase_realtime`.
3. Realtime должен быть включён для проекта (по умолчанию включён).

## Архитектура

```
Next.js (RSC + Server Actions)          Клиентские островки
  ├─ proxy.ts        обновление сессии   ├─ кнопка голоса ──► RPC cast_vote()
  ├─ Server Actions  создать/закрыть/    ├─ Recharts-график (анимированный)
  │                  удалить             └─ Realtime-канал (poll_results)
  └─ RSC-загрузка    getPollBySlug()
        │                                      ▲
        ▼                                      │ postgres_changes (с учётом RLS)
   Supabase PostgreSQL ◄───────────────────────┘
     polls · poll_options · votes · poll_results
```

Ключевые решения:

- **Авторитетные счётчики** (`poll_results.vote_count`) обновляются *в той же
  транзакции*, что и вставка голоса (`cast_vote()`), поэтому не могут разойтись
  с таблицей `votes`. Клиенты подписаны на эту таблицу и перечитывают итоги при
  изменениях — пропущенные/дублирующиеся/задержанные события безопасны, потому
  что состояние сверяется с базой, а не накапливается вслепую.
- **Защита от повторного голосования** — уникальный индекс `(poll_id, voter_id)`,
  где `voter_id` берётся из анонимной сессии, а не от клиента.
- **Публичные ссылки** используют случайные slug; внутренние UUID наружу не
  попадают.
- **Голоса приватны**: RLS позволяет участнику читать только свой голос;
  агрегаты отдаются через публичную таблицу `poll_results`.
- **Без service role**: всё работает либо от имени вызывающего (чтение под RLS,
  запись только владельцем), либо через definer-функции, проверяющие все
  предусловия на сервере.

## Модель безопасности

| Таблица        | SELECT               | INSERT                  | UPDATE/DELETE         |
| -------------- | -------------------- | ----------------------- | --------------------- |
| `polls`        | все                  | только владелец         | только владелец       |
| `poll_options` | все                  | владелец родит. опроса  | владелец родит. опроса|
| `votes`        | только свои строки   | никто (только RPC)      | никто                 |
| `poll_results` | все (агрегаты)       | никто (RPC/триггеры)    | никто                 |

Ошибки RPC возвращаются стабильными кодами (`already_voted`, `poll_closed`,
`rate_limited`, …) и переводятся клиентом на активный язык. Входные данные
проверяются Zod в Server Actions и дублируются CHECK-ограничениями PostgreSQL.

Известное ограничение: очистка cookie создаёт новую анонимную сессию, что даёт
возможность проголосовать снова. Это неотъемлемое свойство анонимных сессий,
осознанный компромисс продукта; ограничитель частоты внутри `cast_vote()`
сдерживает злоупотребления.

## Разработка

```bash
pnpm lint        # ESLint (включая правила react-hooks)
pnpm typecheck   # tsc --noEmit
pnpm test:e2e    # Playwright-набор против http://localhost:3000
pnpm build       # production-сборка
```

E2E-набор покрывает создание, голосование, защиту от дублей, живые обновления,
закрытие опроса, обработку 404 и переключение языка — 14 сценариев.

## Деплой

Деплой на Vercel выполняется из ветки `main`. Интеграция Supabase Marketplace
автоматически поставляет переменные окружения — ручная настройка не нужна.
Прокси-шим в `lib/supabase/fetch.ts` активируется только при наличии
переменных `HTTP(S)_PROXY` и бездействует в продакшене.
